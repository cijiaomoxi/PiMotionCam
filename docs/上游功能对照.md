# 上游功能对照核查 · billw2/pikrellcam → pikrellcam-lite

> **核查对象**：上游 [billw2/pikrellcam](https://github.com/billw2/pikrellcam)（GPL-3.0，master 最后提交 2020-06-08，V4.3.2）
> **对照对象**：本项目 pikrellcam-lite v2.6.0
> **核查日期**：2026-11-13
> **核查方法**：逐文件读取上游源码（`src/config.c`、`src/pikrellcam.c`、`src/display.c`、`src/motion.c`、`src/event.c`、`src/servo.c`、`src/preset.c`、`src/multicast.c`、`src/audio.c`、`src/sunriset.c`、`src/tcpserver.c`、`www/*.php`、`scripts-dist/*`、`etc/*`、`libkrellm/`），抽取其**用户可见的功能点、配置键、HTTP 接口与 FIFO 命令**，再与 pikrellcam-lite 的实现逐条比对。

---

## 一、结论摘要

**没有包含上游的全部功能。**

按"可数、可验证的用户可见功能点"统计（不含实现细节差异）：

| | 上游 | 本项目覆盖 | 覆盖率 |
| --- | --- | --- | --- |
| 有对应实现 | 约 94 项 | 约 46 项 | **约 49%** |
| 部分实现（能力有但形态不同） | — | 约 14 项 | — |
| 明确缺失 | — | 约 34 项 | — |

**结论分三层看：**

1. **网页可视化的核心能力基本对齐** —— 预览、OSD 叠加、区域编辑、双算法灵敏度、预录/补录、事件与缩略图、延时摄影、舵机、预设、定时命令、钩子、密码保护、升级、日志、帮助，中文/英文双语。**这一层基本不缺。**
2. **三个系统性缺口**：
   - **音频子系统整体缺失**（麦克风采集、MP3 编码、音频流、音频触发录像、VU 表）—— 上游约 7 项功能全无；
   - **多播（multicast）整体缺失**（UDP 组播收发、消息去重、ACK、跨主机联动）—— 上游约 6 项功能全无；
   - **OSD 菜单 / 字幕系统缺失** —— 上游那套烧进画面的 OSD 菜单树、动态字幕字符串、字幕背景色/字号，lite 没有（lite 的 OSD 是浏览器 HTML 叠加层，不烧进画面）。
3. **一批"上游特有、依赖其硬件栈"的能力无法平移** —— 上游基于 MMAL 的**硬件运动矢量**（方向检测、爆发检测、矢量叠加、运动统计 CSV、`motion_detects_FIFO` 实时检测流）、**相机成像参数矩阵**（锐度/对比度/亮度/饱和/ISO/快门/白平衡 11 档/图像特效 21 种/测光 4 档/数字变焦）、**循环录像（loop）**、**音频触发**、**FIFO 外部触发录像**。这些要么依赖 MMAL 硬件矢量，要么是一整套独立子系统。

**一句话**：把 pikrellcam-lite 当成"官方 PiKrellCam 的网页功能替代品"是成立的；当成"官方全部功能的完整移植"则不成立。

## 三、配置键对照摘要

上游守护进程配置约 **100 个键** + 相机参数 **19 个** + 预设/OSD 内嵌 **48 个** + 网页 UI **24 个**，合计约 **190 个**。

本项目 `config.json` 共 **约 90 个键**（8 个顶层段）。按语义对应关系：

- **完全对应的（约 35 个）**：`motion_enable`、`motion_pre_capture`、`motion_post_capture`、`motion_event_gap`、`motion_record_time_limit`、`motion_enable`、`motion_stills_enable`（无）、`media_dir`、`archive_target`、`log_file`、`web.port`、`web.password_hash`、`on_motion_begin`、`on_motion_end`、`on_motion_preview_save`、`servo_pan_gpio`、`servo_tilt_gpio`、`servo_pan_min/max`、`servo_tilt_min/max`、`timelapse_convert`（用 ffmpeg 替代）……
- **lite 独有 / 更细的（约 55 个）**：双算法 `algorithms.{far,near}`、多区域 `regions`、`region_presets`、`record.{frame_write_timeout,encoder_close_timeout,encoder_cooldown}`、`camera.{stall_timeout,min_fps,ae_constraint,detect_resolution,detect_fps,jpeg_quality}`、`media.{require_mount,fallback_internal}`、`schedules`、`presets`、`web.{osd,show_vectors,language}` 等。
- **上游有而 lite 没有的（约 100 个）**：几乎全部集中在音频（7）、多播（4）、成像参数（17）、运动矢量/爆发/统计（8）、OSD 菜单与字幕（9）、循环录像（6）、命名模板与序列号（5）、日出日落（3）等域。

## 四、命令协议对照

上游 FIFO（`~/pikrellcam/www/FIFO`）命令表见 `src/pikrellcam.c:1161`，共 30 个顶层命令 + 6 组子命令（`motion` / `display` / `audio` / `preset` / `servo` / `annotate_string`），且**未匹配的命令会回退到"设置同名配置键"**。

本项目 FIFO（`~/.pikrellcam/commands.fifo`）与 `/api/command` 支持 17 个内部命令：

```
record on|off|pause   record_pause   still        tl_start N
tl_hold on|off        tl_end         motion_enable on|off|toggle
motion load_regions NAME             motion limits <mag> <count>
servo goto <name>     servo set <pan> <tilt>
start   stop   restart
```

**已实现的上游命令**：record / record_pause / still / tl_start / tl_hold / tl_end / motion_enable / motion limits / motion load_regions / servo goto / servo set / start / stop / restart。

**未实现的上游命令**：`loop`、`motion_stills_enable`、`motion_detects_fifo_enable`、`display`（整组 OSD 菜单）、`audio`（整组）、`preset`（整组，预设走 HTTP API 而非 FIFO）、`annotate_string`、`inform`、`zoom`、`archive_video` / `archive_still`、`stills_thumbs_rescan`、`fix_thumbs`、`delete_log`、`multicast`、`halt` / `reboot`、`upgrade`、`tl_show_status`、`tl_inform_convert`、`save_config`、以及全部相机/视频参数键。

## 五、缺失项清单（按重要性排序）

| 级别 | 缺失项 | 影响 | 补齐难度 |
| --- | --- | --- | --- |
| 🔴 高 | **音频子系统**（采集/编码/流/触发录像） | 带声音录像完全做不到 | 高（需 ALSA + lame + 音视频同步） |
| 🔴 高 | **多播子系统** | 多台树莓派联动报警做不到 | 中（纯 UDP，约 400 行） |
| 🟠 中 | **OSD 菜单系统 + 字幕系统** | 依赖 OSD 屏的用法做不到 | 中（但需烧进画面，与 lite 的叠加层设计冲突） |
| 🟠 中 | **循环录像（loop）** | 长时间连续录像（不靠移动侦测触发）做不到 | 中 |
| 🟠 中 | **相机成像参数矩阵**（锐度/对比度/饱和/白平衡/ISO/快门/特效/变焦） | 画质无法精细调节 | 中（picamera2 的 `CameraControl` 基本都支持，主要工作量在 UI） |
| 🟡 低 | **运动矢量方向/爆发检测、统计 CSV、检测流 FIFO** | 依赖 MMAL 硬件矢量，帧差分无法平移 | 很高（需换相机栈） |
| 🟡 低 | **日出日落时刻调度** | `dawn/sunrise/sunset` 定时点做不到 | 低（算法约 150 行） |
| 🟡 低 | 录像命名模板、媒体序列号、缩略图修复 | 命名与维护性 | 低 |
| 🟡 低 | 舵机反相 / 三种移动模式 / 静置延迟 | 舵机精细控制 | 低 |
| 🟡 低 | 本地日历归档、归档盘空闲检查、NFS 归档 | 归档体系 | 中 |
| ⚪ 信息 | 网页外观自定义、自定义网页扩展点 | 主题定制 | 低 |

## 六、本项目超出上游的部分

这些不是"补齐上游"，而是上游没有、lite 独有的：

1. **USB 摄像头支持**（上游只支持 CSI/MMAL）
2. **中英双语界面**（上游只有英文）
3. **REST 风格 JSON API**（上游是 PHP 页面 + 表单）
4. **版本化发布目录 + 软链回滚**（上游是 git checkout）
5. **USB / 外部存储可选目标 + 拔盘安全防护**（上游 `media_dir` 只能是本地目录）
6. **原生 C 加速内核 + 自动降级**（上游是纯 C，无 Python 侧对照）
7. **取帧看门狗 / 编码器卡死超时保护**（上游没有等价的防护）
8. **录像完整性校验**（清理缺 `moov` 的坏文件、启动时扫描）
9. **systemd user service + linger**（无需 root 安装）
10. **Debian 13 / libcamera 兼容**（上游依赖已被移除的 MMAL，在现代 Raspberry Pi OS 上无法直接运行）

## 七、复核建议

如果需要把本报告细化到"逐个配置键"级别，对照基线是：

- 上游配置基线：§二 各表 + `src/config.c` 的 `static Config config[]`（约 100 键）+ `camera_parameters[]`（19 键）+ `src/display.c` 的 Adjustment 表（48 键）
- 命令基线：`src/pikrellcam.c:1161` 的 `commands[]`（30 条）+ 6 组子命令表
- 状态文件基线：`src/event.c:820-922` 的 `/run/pikrellcam/state` 字段列表 —— 这是外部脚本可观测状态的完整边界
- HTTP 基线：`www/*.php` 的全部 GET 参数与动作名

**重要提醒**：上游的"未匹配命令即配置键"回退机制意味着其实际可接受命令数远超 `commands[]` 表；做契约比对时不能只按 `commands[]` 表统计。
